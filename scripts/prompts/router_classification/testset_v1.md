# ルーター分類 テスト用質問セット v1

`system_prompt_v1.txt` をPhi-4-miniに投げて分類させ、「期待ルート」と実際の出力を照合して正答率を記録する用。
仮作成のため、実運用の質問傾向に合わせて随時追加・差し替えする想定。

## 使い方(記録欄)

各行の「実際の出力」「正誤」はテスト実施時に追記する。

## 実施記録(router.py Task5 Step3の動作確認時に取得・一部のみ)

router.py実装後の疎通確認(`python router.py "<質問>"`)で、実際にPhi-4-mini + ルールベースフィルタに通した結果。
全20問の網羅テストではなく、各カテゴリの代表例のみ(モデルスワップに時間がかかるため)。

| # | 質問 | 期待ルート | 実際の出力 | 正誤 | 備考 |
|---|------|-----------|-----------|------|------|
| F1 | 今日の東京の天気を教えて(実際はF1相当の言い換え) | FAST | FAST | ○ | |
| C1 | このコードをデバッグして(C1相当) | CODE | CODE | ○ | ルールベース事前フィルタが即確定(Phi-4-mini呼び出しなし) |
| D2 | 来月の家族旅行のスケジュールを組んで(D2相当) | DEEP | DEEP | ○ | |
| X2 | ちょっと相談があるんだけど | CLARIFY | **FAST** | **✗** | **誤判定を確認。「相談」という単語につられてFASTと判定された可能性。system_prompt_v1.txtのFAST/CLARIFYの境界線の記述を要調整(v2で対応)** |

→ 残りの質問(F2-F5, D1,D3-D5, C2-C5, X1,X3-X5)は未実施。Task5 Step4として後日、全20問を通しで流し正答率を算出する。

## 全20問テスト結果(run_testset.py使用)

`サポートAI作製計画/scripts/run_testset.py` で全20問を機械的に流した結果(手動疎通確認より網羅的)。

### system_prompt_v1.txt(初回)

全体正答率: **15/20 (75.0%)** — 完了条件(8割)未達

| カテゴリ | 正答率 |
|---|---|
| FAST | 5/5 (100%) |
| DEEP | 5/5 (100%) |
| CODE | 5/6 (83.3%) |
| CLARIFY | **0/4 (0%)** |

誤判定:
- C4「この正規表現、意図通りにマッチしない原因を教えて」→ 期待CODE、実際DEEP(CODE_TRIGGERSに正規表現デバッグ系のキーワードがなく素通り)
- X1〜X4(CLARIFY全問)→ すべてFASTまたはDEEPに誤判定。Phi-4-miniが「わからない」と答えず近いカテゴリに寄せる挙動が原因と推定。

### system_prompt_v2.txt(改訂後)

改訂内容:
- CLARIFYを選ぶべき具体例(実際に誤判定したX1〜X4)をfew-shot例としてプロンプトに追加し、「自信が持てない場合は必ずCLARIFYを選ぶ」ルールを明記
- `router_rules.py`のCODE_TRIGGERSに「正規表現」「マッチしない」「意図通りに(動作|マッチ)しない」を追加(C4のルールベース即時判定化)
- `router.py`の`SYSTEM_PROMPT_PATH`をv2に切り替え

全体正答率: **18/20 (90.0%)** — 完了条件(8割)達成

| カテゴリ | 正答率 |
|---|---|
| FAST | 3/5 (60.0%) ※新規に2問誤判定 |
| DEEP | 5/5 (100%) |
| CODE | 6/6 (100%) ※C4修正済み |
| CLARIFY | 4/4 (100%) ※v1から改善 |

誤判定(新規に発生・要フォローアップ):
- F3「おすすめのラーメン屋のジャンルを3つ挙げて」→ 期待FAST、実際CLARIFY(CLARIFYへの寄せすぎ、over-correction)
- F4「Pythonのlen()関数って何をするものだっけ?」→ 期待FAST、実際CODE(「Python」「関数」という単語につられた可能性)

**総合判定**: 全体90%で完了条件は満たしているが、FASTカテゴリが新たに弱点化した。次回`system_prompt_v3`を作るなら、「CLARIFYはあくまで最終手段(他3カテゴリの説明に少しでも当てはまるなら基本その3つを優先)」という補足と、「特定の技術用語(Python等)が出ただけではCODEと即断しない(実装/デバッグの依頼が伴う場合のみCODE)」という注記を加える方向で調整するとよい。

## 備考

- X4, X5 はノート本文([[サポートAI作製計画/4日目Phi4ロジック設計.md]])に挙げられている複合タスク例をそのまま採用。
- 複合タスクは初期実装では優先度ルール(CODE > DEEP > FAST)で単一ルートに倒す方針のため、X5の「期待ルート」はCLARIFYではなくCODEとしている。X4はコード実装依頼ではなく「組み込みたい」という計画寄りの表現のため、CLARIFY寄りかDEEP寄りか要検証。
- テスト実施後、誤判定が多いカテゴリがあればカテゴリ説明文(system_prompt_v1.txt)を調整し、v2として保存する。
